01 · วาระการประชุม

สิ่งที่ผู้บริหารควรได้จากรอบนี้

ภาพธุรกิจ

  • ทำไมต้องมีคู่มือการทำงานในระบบ ไม่ใช่ไฟล์แชร์อย่างเดียว
  • วงจรรายได้ RFQ → มัดจำ → โรงงาน → ส่งมอบ
  • ตำแหน่งของ Ops Console ในองค์กร

ผลงานที่ส่งมอบ

  • SPA `/ops/manual` อ่านเอกสารจาก `docs/**/*.md`
  • กรองเอกสารตามสิทธิ์พนักงาน (RBAC)
  • ชุดเอกสาร manual + SOP + matrix
  • UX เมนูซ้ายหดได้ เพื่อโฟกัสงาน

มูลค่า / ความเสี่ยง

  • ลดการเปิดเผยเอกสารผู้ดูแลให้เซลล์ทั่วไป
  • มาตรฐานอบรมและ audit ได้
  • ลดงานนอกระบบและความรู้ในหัวคนเดียว

คำขอตัดสินใจ

  • รับรองใช้ `/ops/manual` เป็นช่องทางคู่มือหลัก
  • กำหนดเจ้าของเอกสารแต่ละฝ่าย
  • รอบอัปเดตเอกสารเมื่อเพิ่มเมนูใหม่

02 · Executive Summary

สรุปหนึ่งหน้า

1แหล่งความจริงของคู่มือ

เอกสาร Markdown ใน repo คือต้นฉบับ — SPA อ่านตรงจากไฟล์ ไม่คัดลอกซ้ำในโค้ด

RBACสิทธิ์เดียวกับ Ops

ใช้ session พนักงานเดิม (`ops_session`) ไม่ต้องโทเค็นแยกสำหรับคู่มือหลัก

15+เอกสารที่จัดกลุ่มแล้ว

คู่มือผู้ใช้ · workflow · SOP · กติกาบอร์ด · เอกสารผู้ดูแล — แสดงตามสิทธิ์

ข้อความหลักสำหรับผู้บริหาร: ทีมงานทำงานบนระบบเดียวกันกับลูกค้าองค์กร — และตอนนี้ “วิธีทำงาน” ก็อยู่ในระบบเดียวกัน โดยเปิดได้เฉพาะเอกสารที่บทบาทนั้นควรเห็น

03 · บริบทธุรกิจ

ทำไมแพลตฟอร์มนี้สำคัญต่อรายได้

Premium Gift Set เป็นธุรกิจ B2B ของขวัญองค์กร / สินค้าพรีเมียมสั่งผลิตจากจีน (สกรีนโลโก้ได้) ราคาบนเว็บเป็นช่วงโดยประมาณ — รายได้จริงเริ่มเมื่อมี RFQ และมัดจำ

ลูกค้าเลือกสินค้า→ ขอใบเสนอราคา→ เซลล์เปิดออเดอร์→ มัดจำ / อนุมัติสลิป→ สั่งโรงงานจีน→ รับของ · ส่งมอบไทย

ความเสี่ยงเดิม

  • ความรู้ขั้นตอนอยู่ในหัวเซลล์/บัญชี
  • ไฟล์คู่มือกระจัดกระจาย — อัปเดตไม่ทันหน้าจอจริง
  • เอกสารเทคนิค/deploy อาจหลุดถึงคนที่ไม่ควรเห็น

ทิศทางที่เลือก

  • คู่มืออยู่ในเว็บ Ops ที่ล็อกอินแล้ว
  • ต้นฉบับเป็น Markdown ใน `docs/` ที่ทีมพัฒนาดูแลคู่โค้ด
  • กรองตามสิทธิ์เดียวกับเมนูปฏิบัติการ

04 · ภาพรวมแพลตฟอร์ม

สามชั้นที่ผู้บริหารควรจำ

1) เว็บสาธารณะ

แคตตาล็อก · RFQ · ตะกร้าขอราคา · ติดตามออเดอร์ด้วยลิงก์ · ชำระ PromptPay/สลิป · แจ้งปัญหา

ลูกค้าจัดซื้อ — ไม่ต้องมี username Ops

2) Ops Console

CRM · ใบเสนอราคา · ออเดอร์ · บอร์ดงาน · อนุมัติยอด · โรงงาน · รับเข้า · บัญชี · รายงาน

พนักงานล็อกอินด้วยอีเมล/รหัสผ่าน หรือ Google

3) คู่มือ / ความรู้

SPA คู่มือการทำงาน `/ops/manual` + ชุด `docs/manual` + SOP วงจร + Function matrix

เชื่อมกับสิทธิ์บทบาทใน Ops

ชั้นที่ 3 คือผลงานรอบนี้ — ทำให้ความรู้ปฏิบัติการกลายเป็นสินทรัพย์องค์กร ไม่ใช่ไฟล์ส่วนตัว

05 · สิ่งที่ส่งมอบรอบนี้

Work Manual SPA — สิ่งที่สร้างเสร็จ

รายการรายละเอียดผลต่อองค์กร
หน้า `/ops/manual` SPA อ่านสารบัญ + เนื้อหา Markdown · ค้นหา · กระโดดหัวข้อ พนักงานเปิดคู่มือในที่ทำงานจริง ไม่สลับไปหาไฟล์นอกระบบ
API `/api/ops/manual` โหลด TOC/เอกสารหลังตรวจ session + สิทธิ์ ควบคุมการเข้าถึงฝั่งเซิร์ฟเวอร์ ไม่พึ่งซ่อนเมนูอย่างเดียว
Catalog สิทธิ์ จัดกลุ่มเอกสาร: เริ่มต้น / คู่มือหลัก / วงจร / ขาย / เทคนิค / ผู้ดูแล เซลล์ไม่เห็นเอกสาร deploy / NAS / Git ของผู้ดูแล
เมนูซ้ายหดได้ ปุ่มหด/ขยายแถบ Ops · จำสถานะในเบราว์เซอร์ หน้าจอคู่มือมีพื้นที่อ่านมากขึ้นบนโน้ตบุ๊ก
อัปเดตเอกสารกำกับ INDEX · Function matrix · ลิงก์ในเมนูระบบ มีร่องรอย audit ว่าคู่มือครอบคลุม route ใดบ้าง

06 · ชุดเอกสารต้นฉบับ

เอกสารที่ SPA ดึงมาแสดง

คู่มือหลัก (`docs/manual/`)

  • 00 INDEX — สารบัญชุดเอกสาร
  • 01 PROJECT RECORD — บันทึกโครงการ
  • 02 USER MANUAL — คู่มือใช้งานบท 1–8
  • 03 WORKFLOWS — Sequence / State
  • 04 ER DIAGRAMS — โครงข้อมูล
  • 05 FUNCTION MATRIX — ทุก route ↔ role

เอกสารปฏิบัติการ / กำกับ

  • SOP-CYCLE — วงจรสั่งผลิต–ส่งมอบ
  • SOP-CHECKLIST — เช็กลิสต์ลงมือทำ
  • OPS-CONSOLE — คู่มือคอนโซล
  • BOARD-STATUS-RULES — กติกาบอร์ด
  • เอกสารผู้ดูแล: Staging / NAS / Git (เฉพาะ admin)

หลักการ: แก้ Markdown ใน repo → พนักงานเห็นเนื้อหาใหม่ทันทีหลัง deploy/รีสตาร์ท — ไม่ต้องทำสไลด์ซ้ำทุกครั้งที่เปลี่ยนขั้นตอน

07 · การกำกับสิทธิ์

ใครเห็นอะไร — สรุปผู้บริหาร

บทบาทตัวอย่างที่เปิดได้ที่ถูกปิดโดยค่าเริ่มต้น
Sales คู่มือผู้ใช้ · Workflow · SOP · Ops Console · กติกาบอร์ด Staging deploy · NAS Portainer · Git remotes
Accountant SOP / วงจร · บทการเงินในคู่มือ (ถ้ามีสิทธิ์รายงาน/บัญชี) เอกสารโครงสร้าง infra ผู้ดูแล (ถ้าไม่ใช่ admin)
Viewer เอกสารภาพรวม / อ่านอย่างเดียวตาม permission อ่าน เอกสารเขียนราคา / ผู้ดูแลระบบ

สิทธิ์ใช้ชุดเดียวกับเมนู Ops (`quotes.read`, `finance.read`, `factory.read`, `users.read`, …) — ไม่สร้างระบบสิทธิ์ขนาน

08 · ธรรมาภิบาลข้อมูล

ทำไมเรื่องนี้ถึงเป็นวาระผู้บริหาร

ความลับปฏิบัติการ

ขั้นตอนโรงงาน ต้นทุน และวิธี deploy ไม่ควรกระจายเท่าไฟล์แชร์ทั้งบริษัท

ความต่อเนื่องธุรกิจ

เมื่อมีพนักงานใหม่หรือสลับกะ — คู่มือมาตรฐานลด downtime ของเซลล์/บัญชี

ตรวจสอบได้

Function matrix ผูก route กับบทคู่มือ — ใช้ตรวจว่ามีหน้าที่ยังไร้คำอธิบาย

สิ่งที่ระบบบังคับ

  • ต้องล็อกอิน Ops ก่อนอ่าน
  • API ปฏิเสธ 401/403 เมื่อไม่มีสิทธิ์
  • เอกสารถูกคัดออกจากสารบัญตามบทบาท

สิ่งที่ยังต้องมีวินัยคน

  • เจ้าของเอกสารอัปเดตเมื่อเปลี่ยนขั้นตอน
  • ไม่แปะรหัสผ่าน/ข้อมูลลูกค้าใน Markdown
  • หัวหน้าฝ่ายรีวิว SOP รายไตรมาส

10 · มูลค่าทางธุรกิจ

ผลที่คาดหวัง (วัดได้)

ตัวชี้วัดก่อนเป้าหมายหลังใช้คู่มือในระบบ
เวลาอบรมพนักงานใหม่ถึงทำงาน RFQ ได้ พึ่งพี่เลี้ยง / ถามซ้ำ ลดรอบถามซ้ำ — มีเส้นทางอ่านตามบทบาท
ความผิดพลาดขั้นตอน (สั่งโรงงานก่อนมัดจำ ฯลฯ) พึ่งความจำ + แชท SOP + กติกาบอร์ดอยู่ในมือขณะทำงาน
การเปิดเผยเอกสาร infra แชร์โฟลเดอร์กว้าง เฉพาะ platform admin ใน SPA
เอกสารคลาดเคลื่อนจากหน้าจอจริง อัปเดตช้า / คนละเวอร์ชัน ต้นฉบับคู่โค้ด + matrix ตรวจ route

11 · เส้นทางสาธิต 5 นาที

Demo ที่แนะนำให้ผู้บริหารดูสด

  1. ล็อกอิน `/ops/login` ด้วยบัญชีผู้ดูแล
  2. เปิดเมนู ระบบ → คู่มือการทำงาน หรือ `/ops/manual`
  3. เลือก Workflow diagrams / SOP ทั้งวงจร — แสดงว่าเนื้อมาจากไฟล์ MD
  4. กด หดเมนูซ้าย เพื่อให้พื้นที่อ่านคู่มือ
  5. (ถ้ามี) สลับบัญชีเซลล์ — สารบัญจะไม่มีเอกสาร Staging / NAS / Git
URL ท้องถิ่นปัจจุบัน: http://localhost:3001/ops/manual · โปรดักชันจะอยู่ภายใต้โดเมน Ops ขององค์กรหลัง deploy

12 · สถาปัตยกรรมแบบผู้บริหาร

ไหลของข้อมูลคู่มือ (ไม่ลึกโค้ด)

พนักงานล็อกอิน Ops→ ตรวจ role / permission→ สร้างสารบัญที่อนุญาต→ อ่านไฟล์ docs/*.md→ แปลงเป็น HTML ปลอดภัย→ แสดงใน SPA

เทคโนโลยีหลักของแพลตฟอร์ม

  • Next.js 15 + React 19 (เว็บและ Ops)
  • SQLite Ops · MySQL catalog · Strapi CMS
  • MinIO เก็บไฟล์ · Docker / Portainer deploy

จุดที่ผู้บริหารควรสนใจ

  • ความรู้ถูกเวอร์ชันใน Git เหมือนซอฟต์แวร์
  • Standalone deploy คัดลอกโฟลเดอร์ `docs/` ไปด้วย
  • ไม่มีฐานข้อมูลคู่มือแยก — ลดภาระดูแล

13 · ความปลอดภัยและการเข้าถึง

ขอบเขตการป้องกัน

ที่ครอบคลุมแล้ว

  • บังคับ session Ops ก่อนเข้าหน้าคู่มือ
  • กรองเอกสารระดับรายไฟล์ตาม audience
  • กัน path traversal ตอนอ่านไฟล์
  • แปลง Markdown เป็น HTML แบบ escape
  • หน้าคู่มือตั้ง robots noindex

ข้อจำกัดที่ควรรับทราบ

  • ผู้มีสิทธิ์ยังคัดลอกข้อความออกนอกระบบได้
  • SOP แบบโทเค็น `/sop` ยังมีแยก (สำหรับเคสแชร์ลิงก์)
  • คุณภาพเอกสารขึ้นกับวินัยอัปเดตของเจ้าของเรื่อง

15 · แผนถัดไป (เสนอ)

Roadmap หลังรับรองจากผู้บริหาร

30 วัน

  • แต่งตั้งเจ้าของเอกสารรายกลุ่ม
  • อบรมสั้น เซลล์/บัญชี ใช้ `/ops/manual`
  • เก็บ feedback หัวข้อที่ขาด

60 วัน

  • ผูกภาพหน้าจอจริงในบทคู่มือสำคัญ
  • เช็ค matrix ครบทุก route ใหม่
  • ทบทวน gate สิทธิ์รายเอกสาร

90 วัน

  • วัดเวลาอบรมพนักงานใหม่
  • รีวิว SOP รายไตรมาสโดยหัวหน้าฝ่าย
  • พิจารณาค้นหาเต็มข้อความข้ามเอกสาร

16 · คำขอตัดสินใจ

สิ่งที่ขอจากผู้บริหารวันนี้

ขออนุมัติ

  • ใช้ `/ops/manual` เป็นช่องทางคู่มือปฏิบัติการหลัก
  • ให้หัวหน้าฝ่ายเป็นเจ้าของเนื้อหาในกลุ่มของตน
  • กำหนดว่าเอกสาร deploy/infra อยู่เฉพาะ admin

ขอทรัพยากร

  • เวลา 1–2 ชม./ฝ่าย สำหรับรีวิวเอกสารรอบแรก
